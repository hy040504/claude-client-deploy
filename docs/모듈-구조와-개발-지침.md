# 구조와 개발 지침

## 모듈 경계

```text
chat-cli.js / chat-tui.js
  └─ cli/chat-entry.js → chat/menu.js
       ├─ accounts/ + cli/account-commands.js
       ├─ browser/ 로그인
       └─ chat/session-cli.js 또는 chat/session-tui.js
            └─ runtime/create-runtime.js → claude/ + http/ + state/

index.js → cli/index-cli.js
  ├─ 계정·Gmail·로그아웃: config만 생성
  └─ Claude API 명령: 계정에 고정된 runtime 생성

scripts/*-login.js → cli/login-entry.js → browser/login-cli.js

browser/ → gmail/login-mail.js + gmail/latest-claude-mail.js
  ├─ direct → gmail-client.js + message-parser.js
  └─ relay  → relay-client.js
```

`createAppConfig({ accountId })`는 공통 환경 설정에 계정 정보와 독립된 저장 경로를 적용합니다. 하위 모듈은 전달받은 config를 사용하며 환경 변수에서 Gmail token을 다시 읽지 않습니다. `createRuntime({ config })`는 해당 설정을 유지한 채 API, 쿠키, 클라이언트 상태를 조립합니다.

Gmail OAuth 결과는 `accounts/account-store.js`에 저장합니다. `.env`는 공통 설정과 기존 default 계정의 초기 설정만 담당합니다. 인증 실패 후 다른 공급자나 계정으로 자동 전환하지 않습니다.

`chat/menu.js`가 계정 전환, 로그인, 대화 선택·이름 변경·삭제를 공유합니다. `session-cli.js`와 `session-tui.js`는 채팅 표시·입력을 담당하며 `claude/conversation-data.js`의 대화 파서를 API와 함께 사용합니다. `chat/conversation-data.js`는 기존 import 경로를 유지하고 화면의 모델 선택 목록만 관리합니다. TUI의 응답 표시 애니메이션은 완료된 API 응답을 순차 표시하는 기존 동작이며 네트워크 스트리밍과 구분합니다.

이전 `prompt-chat*.js`와 `src/prompts/chat-prompt*.js`는 얇은 호환 진입점입니다. 기능 수정은 `src/chat`에서 합니다. `client-prompt.js`는 개별 명령 디버깅용 메뉴입니다.

## 유지한 동작

- Claude 대화 API, SSE 파싱, v2 목록과 기존 목록·브라우저 fallback을 유지합니다.
- background, interactive, 간소화 로그인 경로를 유지합니다.
- 대화 전체 삭제는 `DELETE ALL` 확인 후 실행합니다.
- Rammerhead import는 재도입하지 않습니다.
- 기존 작업 기록은 [2026-05-24 handover](archive/2026-05-24-handover.txt)에 보관합니다. 현재 동작과 사용법은 README와 본 docs를 기준으로 합니다.

## 검증

```bash
npm run check:format
npm run check:syntax
npm run check:jsdoc
npm test
# 위 네 검사를 한 번에 실행
npm run check
```

테스트는 Node 내장 test runner를 사용합니다. 코드 구조를 분석하는 Acorn과 포맷을 유지하는 Prettier는 개발 의존성이며 `npm ci`로 함께 설치됩니다. 임시 파일은 `tmp/tests` 아래에 만들고 정리합니다. 외부 Google·Claude 요청을 보내지 않습니다.

주요 회귀 조건:

- 다른 계정의 Gmail token, 쿠키, 캡처 헤더, 조직 ID, Chrome 프로필을 상속하지 않는다.
- 기본 계정 전환이 실행 중인 runtime의 경로를 바꾸지 않는다.
- 인증한 주소가 등록 주소와 다르면 저장하지 않는다.
- OAuth callback은 `state`를 검증하고 취소·timeout을 처리한다.
- relay 요청마다 선택한 계정의 token을 전달한다.
- 로그아웃 뒤 삭제한 상태 파일을 다시 저장하지 않는다.
- 새 실행 파일과 기존 호환 명령이 모두 실행된다.
- 이전 인증 메일과 잘못된 발신자·링크를 자동 로그인에 사용하지 않는다.
- 메일의 MIME 순서에 관계없이 일반 텍스트 본문을 우선한다.
- 대화 목록 조회 실패·페이지 누락을 성공으로 처리하지 않는다.
- 실패한 메시지 전송이 이어쓰기 상태를 덮어쓰지 않는다.
- API와 TUI의 메시지 ID 해석이 같고 깊은 중첩·순환 참조도 처리한다.
- 종료한 작업의 타이머를 정리하고 원본 Chrome 프로필 삭제를 거부한다.

실제 Google 동의 및 Claude 로그인·대화 요청은 환경별 수동 통합 검증이 필요합니다. TUI 화면은 TTY가 있는 터미널에서 실행합니다.

## 변경 규칙

[AGENTS.md](../AGENTS.md)를 따릅니다. 함수 설명, 매개변수, 반환값을 한국어 JSDoc으로 남기고 제약과 이유를 짧게 설명합니다. 공통 기능은 두 화면에 복사하지 말고 공유 모듈에 추가합니다.

계정 저장소 경로나 Chrome 프로필을 바꾸는 작업은 기존 데이터 이전 방식을 함께 문서화하세요. 공개 CLI 출력에 refresh token이나 relay session token을 포함하지 않습니다.

## 작은 모듈의 역할

| 파일                              | 책임                                                    |
| --------------------------------- | ------------------------------------------------------- |
| `src/gmail/message-parser.js`     | MIME 본문을 한 번 순회해 텍스트와 버튼 링크를 추출      |
| `src/gmail/login-mail.js`         | 이번 로그인 이후 도착한 인증 메일을 기다리고 중단 처리  |
| `src/gmail/latest-claude-mail.js` | direct/relay 선택과 감시 중 OAuth 클라이언트 재사용     |
| `src/claude/conversation-data.js` | API와 화면이 사용하는 대화 구조 해석                    |
| `src/cli/login-entry.js`          | 로그인 스크립트의 계정 선택·도움말·실패 종료 코드       |
| `src/shared/async.js`             | 작업 완료 후 남는 타이머 없이 대기 시간 제한            |
| `scripts/lib/source-files.js`     | 실행 위치와 관계없이 프로젝트 소스만 검사 대상으로 수집 |
| `scripts/lib/jsdoc-analysis.js`   | 구문 트리로 함수와 JSDoc을 연결해 인자·반환값을 검사    |

상세 규칙은 [코드 작성과 검증 규칙](코드-작성과-검증-규칙.md)을 참고합니다.
