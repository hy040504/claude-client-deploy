# 코드 작성과 검증 규칙

## 언어와 이름

- 주석, JSDoc 설명, 사용자 안내는 한국어로 작성합니다. 인코딩은 UTF-8을 사용합니다.
- 함수·변수·파일 이름은 역할을 드러내는 영어 이름을 사용합니다. 기존 공개 함수와 import 경로의 호환성을 지킵니다.
- API 필드, HTTP 헤더, 환경 변수, 라이브러리 이름은 원래 표기를 유지합니다. 예를 들어 `refresh_token`을 한국어 필드로 바꾸면 Google API와 호환되지 않습니다.
- `fallback`은 첫 경로가 실패했을 때 시도하는 대체 경로, `polling`은 일정 간격의 반복 조회, `jar`는 세션 쿠키 저장소를 뜻합니다. 설명에서는 가능하면 뜻을 풀어서 적습니다.

## JSDoc 작성

[AGENTS.md](../AGENTS.md)의 함수 주석 규칙을 따릅니다. 한 줄 설명, 모든 `@param`, `@returns`를 작성하고 호출자가 처리해야 할 실패에는 `@throws`를 추가합니다. 반환값이 없어도 `@returns {void} 반환값 없음`을 표시합니다.

```js
/**
 * 계정 전환이 진행 중인 채팅에 영향을 주지 않도록 실행 시 선택한 설정을 고정한다.
 * @param {object} config - 선택한 계정의 인증 정보와 저장 경로
 * @param {string} conversationId - 이어서 대화할 기존 대화 ID
 * @returns {Promise<object>} 계정과 대화에 고정된 세션
 * @throws {Error} 해당 계정의 로그인 정보가 없으면 발생
 */
```

타입은 실제 반환값과 맞춥니다. 실패 시 `null`을 반환하면 `Promise<object|null>`처럼 적고, 예외를 던지는 경우와 구분합니다. 객체 인자는 먼저 `options`를 설명한 다음 필요하면 `options.query` 같은 속성을 설명합니다.

“데이터를 처리한다”, “고도화된 로직”처럼 역할을 알 수 없는 설명은 피합니다. “응답에서 빠진 부모 메시지 ID를 대화 상세 조회로 보충한다”처럼 입력, 목적, 실패 시 동작을 연결해서 씁니다. 코드로 드러나는 줄마다 주석을 추가하지 말고, 명확한 이름과 작은 함수로 흐름을 설명합니다.

## 자동 검사 범위

`check:jsdoc`은 정규식으로 함수 선언 줄만 찾던 방식을 Acorn 구문 트리 분석으로 바꿨습니다.

- 일반·export 함수, 중첩 함수, 변수에 담은 화살표 함수, 객체·클래스 메서드, 함수 대입문을 검사합니다.
- 함수 설명과 인자·반환값 설명에 한국어가 있는지 확인합니다.
- 실제 매개변수의 개수와 이름을 `@param`과 비교합니다. 선택 인자와 나머지 인자도 확인하며 객체 속성 설명은 별도 인자로 세지 않습니다.
- 설명 없이 영어만 적힌 주석도 찾습니다.

검사 통과가 설명의 정확성까지 보장하지는 않습니다. 인자로 직접 전달하는 익명 콜백, 타입의 의미, 예외 조건과 설명의 일치 여부는 수동으로도 검토해야 합니다. 복잡한 콜백은 역할이 드러나는 이름을 붙여 분리하고 JSDoc을 작성합니다. 이 자동 검사 범위가 AGENTS.md의 작성 규칙을 대체하지는 않습니다.

## 형식과 검증 명령

```bash
npm ci
npm run format
npm run check
```

`format`은 명시한 소스 폴더, 루트 JavaScript, README, docs의 Markdown, 프로젝트 설정만 정리합니다. 세션 파일이나 Chrome 프로필은 대상으로 삼지 않습니다. 공백 2칸과 LF 줄바꿈을 사용하며 `.editorconfig`와 `.prettierrc.json`에 설정을 보관합니다. `.gitattributes`는 Windows에서 다시 체크아웃해도 소스의 LF 줄바꿈이 유지되도록 합니다. 설정과 CLI 옵션은 [Prettier 공식 문서](https://prettier.io/docs/options) 및 [CLI 안내](https://prettier.io/docs/cli)를 기준으로 합니다.

`check`는 다음 순서로 실행합니다.

1. `check:format`: 포맷 차이가 있는지 확인합니다.
2. `check:syntax`: 실행 파일과 소스의 JavaScript 문법을 검사합니다.
3. `check:jsdoc`: 함수 설명과 실제 선언을 비교합니다.
4. `test`: Node 내장 테스트 실행기로 동작을 검증합니다.

테스트는 실제 계정 파일 대신 임시 저장소와 로컬 모의 서버를 사용합니다. 외부 Google 동의, 실제 Claude 메시지 전송, 실제 Chrome 인증 화면은 자동 검증 범위에 포함되지 않습니다.

## 새 코드를 추가할 위치

메일 본문 처리는 `gmail/message-parser.js`, 새 인증 메일 대기는 `gmail/login-mail.js`, 대화 응답 해석은 `claude/conversation-data.js`에서 수정합니다. 화면에 같은 기능을 복사하기 전에 공유 모듈로 처리할 수 있는지 확인합니다.

계정 정보는 전달받은 `config`를 사용합니다. 하위 함수에서 `.env`의 Gmail token을 다시 읽으면 다른 계정의 인증을 가져올 수 있습니다. 종료 후 저장할 파일 경로도 실행 중 선택한 계정의 설정을 유지해야 합니다.
