# 계정 설정과 기존 환경 이전

## 계정의 의미

계정 ID 하나는 Gmail 사서함, Claude 로그인 주소, Claude 쿠키·브라우저 프로필·이어쓰기 파일을 묶습니다. Gmail 주소와 Claude 로그인 주소가 같으면 주소를 한 번만 입력하면 됩니다. 전달받는 메일이나 별칭을 사용하면 마지막 인자에 Claude 주소를 지정합니다.

```bash
node index.js account-add personal personal@gmail.com direct
node index.js account-add work inbox@gmail.com relay alias@example.com
node index.js account-list
node index.js account-use personal
```

ID는 영문 소문자·숫자로 시작하는 1~64자의 소문자, 숫자, `_`, `-`입니다. `default`와 Windows 예약 이름은 새 계정 ID로 사용할 수 없습니다. 같은 ID를 다시 추가하면 기존 인증을 덮어쓰지 않고 오류를 반환합니다.

## 직접 Gmail 연결

Google Cloud 콘솔의 메뉴별 설정, Testing 상태의 token 만료, 서버 분리 시 추가 설정은 [구글 클라우드와 지메일 인증 설정](구글-클라우드-지메일-인증-설정.md)을 참고하세요.

1. Google Cloud 프로젝트에서 Gmail API를 활성화하고 OAuth 동의 화면을 설정합니다.
2. 데스크톱 앱용 OAuth 클라이언트를 만들고 `.env`에 `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`을 설정합니다.
3. 테스트 상태의 OAuth 앱이라면 사용할 Gmail 계정을 테스트 사용자로 등록합니다.
4. `node index.js --account personal gmail-auth direct`를 실행합니다.
5. 출력된 URL을 브라우저에서 열고 **personal에 등록한 Gmail 주소**로 동의합니다.

Google의 [데스크톱 OAuth 안내](https://developers.google.com/identity/protocols/oauth2/native-app)에 맞춰 loopback callback, `state`, PKCE를 사용합니다. `login_hint`는 계정 선택을 돕는 값이고, 저장 전 [Gmail `users.getProfile`](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users/getProfile)로 실제 인증 주소를 확인합니다. 등록한 Gmail 주소와 다르면 토큰을 저장하지 않습니다.

기본 callback은 `http://127.0.0.1:3000/oauth2callback`입니다. 포트 충돌 시 `GMAIL_AUTH_PORT`를 바꿀 수 있습니다. callback 서버의 기본 바인딩도 `127.0.0.1`이며 기본 대기 시간은 5분입니다. 원격 서버에서 OAuth를 처리하려면 relay 모드를 사용합니다.

```bash
node index.js --account personal gmail-latest
npm run login:it -- --account personal
node chat-tui.js --account personal
```

직접 연결의 OAuth 클라이언트 ID·secret은 공통 설정이고 refresh token은 계정별로 저장합니다. 계정 추가만으로 다른 계정의 refresh token을 복제하지 않습니다.

## relay 연결

```env
GMAIL_RELAY_SERVER_URL=https://gmail.example.com
GMAIL_RELAY_API_KEY=
```

```bash
node index.js account-add work work@gmail.com relay
node index.js --account work gmail-auth relay
node index.js account-use work
```

Google refresh token은 서버가 보관하고, CLI는 계정에 연결된 relay session token과 해당 서버 주소를 저장합니다. 서버에서 돌려준 인증 주소도 등록한 계정과 일치해야 합니다. 서버 구현은 [relay 규격](지메일-중계-서버-연동-규격.md)을 참고하세요.

기존 계정의 연결 방식을 바꾸려면 `gmail-auth direct` 또는 `gmail-auth relay`로 다시 인증합니다. 성공 후 해당 계정의 이전 방식 자격 증명을 교체합니다. relay가 실패하거나 설정이 빠져도 다른 사서함으로 연결하지 않습니다.

## 기존 단일 계정 호환

`default`는 기존 `.env` 설정을 읽는 예약 계정입니다. 기존 파일을 옮기거나 삭제하지 않습니다.

| 설정                                                     | 적용 범위                                |
| -------------------------------------------------------- | ---------------------------------------- |
| `GMAIL_REFRESH_TOKEN`, `GMAIL_RELAY_SESSION_TOKEN`       | 저장소에 아직 인증하지 않은 default 계정 |
| `GMAIL_USER_EMAIL`, `CLAUDE_LOGIN_EMAIL`                 | default 계정의 초기 주소                 |
| `COOKIE_JAR_PATH`, `CLIENT_STATE_PATH`, `LAST_CHAT_PATH` | default 계정 상태 파일                   |
| `LATEST_CLAUDE_CODE_PATH`, `BROWSER_PROFILE_PATH`        | default 계정 코드·Chrome 프로필          |
| `ORG_ID`, `CAPTURED_COOKIE`, `CAPTURED_HEADERS`          | default 계정에만 적용                    |
| `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`                 | 직접 연결 계정 공통 OAuth 앱             |
| `ACCOUNTS_PATH`, `ACCOUNTS_DATA_PATH`                    | 전체 계정 저장소·세션 루트               |

`default`를 다시 Gmail 인증하면 새 자격 증명은 `accounts.json`에 저장됩니다. 그 이후에는 저장소의 값이 기존 `.env` token보다 우선합니다. `.env`는 자동으로 수정하지 않습니다. 인증 완료를 확인한 뒤 사용하지 않는 기존 token은 직접 정리할 수 있습니다.

새 이름의 계정을 추가하면 깨끗한 Claude 상태 디렉터리를 사용하므로 Claude 로그인도 처음 한 번 진행해야 합니다.

## 선택과 저장

- 실행 우선순위: 명령 앞의 `--account <id>` > `CLAUDE_ACCOUNT` > 저장된 활성 계정 > `default`.
- `account-use`는 다음 실행의 기본값을 바꿉니다. 이미 열린 메뉴는 현재 계정을 유지하며 메뉴 9번으로 직접 전환할 수 있습니다.
- 채팅 메뉴의 하위 프로세스와 런타임은 계정 ID를 전달받습니다.
- 계정 파일은 잠금과 임시 파일 교체로 저장합니다. 손상된 파일을 빈 저장소로 덮어쓰지 않습니다.
- 강제 종료 뒤 `.data/accounts.json.lock`이 남으면 모든 계정 관리·인증 프로세스가 종료됐는지 확인한 뒤 그 잠금 파일만 제거하세요.
- 계정별 Chrome 프로필은 동시 사용 시 잠길 수 있습니다. 같은 계정으로 여러 로그인 브라우저를 동시에 열지 마세요.

자격 증명은 로컬 JSON에 저장하며 암호화 저장소는 아닙니다. POSIX에서는 디렉터리 `0700`, 계정 파일 `0600` 권한으로 생성합니다. Windows에서는 사용자 디렉터리 ACL을 따릅니다. 백업 시에도 token과 쿠키를 포함한 민감 자료로 취급하세요.

## 로그아웃

```bash
node index.js --account work logout
```

해당 계정의 Claude 쿠키, 클라이언트 상태, 최근 대화, 인증 코드, Chrome 프로필을 정리합니다. 다른 계정과 Gmail 자격 증명은 유지합니다. Google 접근 권한 철회와 원격 Claude 세션 전체 종료를 수행하는 명령은 아닙니다.
