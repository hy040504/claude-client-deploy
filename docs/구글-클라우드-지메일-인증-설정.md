# 구글 클라우드와 지메일 인증 설정

이 문서는 현재 프로젝트에서 여러 Gmail 계정을 연결하기 위한 Google Cloud 설정과, 추후 Gmail relay 서버를 분리할 때 필요한 설정을 설명합니다.

GCP에서는 앱 공통 설정을 하고, 각 Gmail 계정은 OAuth 동의를 진행합니다. 현재의 로컬 직접 연결 방식은 GCP 서버 배포 없이 사용할 수 있습니다.

## 1. 연결 방식 선택

| 구분                           | 현재 로컬 직접 연결          | 추후 relay 서버 연결                               |
| ------------------------------ | ---------------------------- | -------------------------------------------------- |
| 프로젝트 인증 방식             | `direct`                     | `relay`                                            |
| Google OAuth 클라이언트 유형   | Desktop app                  | Web application                                    |
| Google 인증 응답 수신 위치     | 실행 중인 PC의 로컬 callback | 서버의 HTTPS callback                              |
| Google refresh token 저장 위치 | 로컬 계정 저장소             | 서버의 계정별 저장소                               |
| 현재 CLI가 보관하는 자격 증명  | 계정별 Google refresh token  | 계정별 relay session token                         |
| 현재 구현 범위                 | 직접 연결 구현               | 클라이언트와 연동 규격 구현, 운영 서버는 별도 구축 |

현재 구현은 여러 계정에 같은 OAuth 클라이언트 ID·secret을 사용하고, 각 계정에서 발급받은 token을 분리해서 저장합니다. 기존 프로젝트의 Gmail API와 적절한 유형의 OAuth 클라이언트가 준비돼 있다면 해당 설정을 재사용할 수 있습니다.

## 2. Google Cloud 공통 설정

[Google Cloud Console](https://console.cloud.google.com/)에서 사용할 프로젝트를 선택한 뒤 진행합니다.

| 순서 | 콘솔 위치                          | 설정 내용                                                  |
| ---- | ---------------------------------- | ---------------------------------------------------------- |
| 1    | 프로젝트 선택                      | 기존 프로젝트 선택 또는 새 프로젝트 생성                   |
| 2    | API 및 서비스 → 라이브러리         | **Gmail API** 검색 후 사용 설정                            |
| 3    | Google Auth Platform → Branding    | 앱 이름, 사용자 지원 이메일, 개발자 연락처 입력            |
| 4    | Google Auth Platform → Audience    | 개인 Gmail 계정들을 연결한다면 **External** 선택           |
| 5    | Audience → Test users              | Testing 상태에서 사용할 Gmail 주소를 각각 추가             |
| 6    | Google Auth Platform → Data Access | `https://www.googleapis.com/auth/gmail.readonly` 범위 추가 |

조직 외 개인 계정을 사용하는 이 프로젝트에서는 External 설정을 기준으로 설명합니다. 조직 내부 전용 앱은 조직 환경에 맞는 사용자 유형을 선택합니다. [Google OAuth 동의 화면 설정 안내](https://developers.google.com/workspace/guides/configure-oauth-consent)

현재 코드는 메일 본문과 로그인 링크를 읽기 위해 `gmail.readonly`를 요청합니다. [Google Gmail 권한 범위 안내](https://developers.google.com/workspace/gmail/api/auth/scopes)

## 3. 로컬 직접 연결용 OAuth 클라이언트 생성

1. **Google Auth Platform → Clients → Create client**로 이동합니다.
2. 애플리케이션 유형을 **Desktop app**으로 선택합니다.
3. 알아보기 쉬운 이름을 입력하고 생성합니다.
4. 발급된 **Client ID**와 **Client secret**을 확인합니다.

이 절차는 Google의 [Gmail Node.js 시작 안내](https://developers.google.com/workspace/gmail/api/quickstart/nodejs)를 기준으로 합니다.

현재 프로젝트의 기본 callback 주소는 다음과 같습니다.

```text
http://127.0.0.1:3000/oauth2callback
```

인증 명령을 실행하면 해당 PC에서 임시 callback 서버를 엽니다. 출력된 인증 URL은 그 PC의 브라우저에서 여세요. 포트 충돌이 있으면 `.env`의 `GMAIL_AUTH_PORT`를 변경할 수 있습니다.

Desktop app은 로컬 loopback callback을 사용하는 방식입니다. 뒤에서 설명하는 Web application의 승인된 리디렉션 URI 등록 절차와 구분합니다. [Google 데스크톱 OAuth 안내](https://developers.google.com/identity/protocols/oauth2/native-app)

## 4. 프로젝트 환경 변수 설정

프로젝트 루트의 `.env`에 다음 값을 설정합니다. `.env`가 없다면 `.env.example`을 복사해서 만듭니다. 기존 파일이 있다면 필요한 항목만 수정합니다.

```env
GMAIL_AUTH_MODE=direct
GMAIL_CLIENT_ID=발급받은_client_id
GMAIL_CLIENT_SECRET=발급받은_client_secret
```

callback 주소를 바꿔야 할 때 사용하는 설정은 다음과 같습니다. 기본값으로 사용할 수 있으면 변경할 필요가 없습니다.

```env
GMAIL_AUTH_HOST=127.0.0.1
GMAIL_AUTH_BIND_HOST=127.0.0.1
GMAIL_AUTH_PORT=3000
GMAIL_AUTH_PATH=/oauth2callback
GMAIL_AUTH_TIMEOUT_MS=300000
```

새 계정의 refresh token은 인증 명령이 계정 저장소에 저장합니다. `.env`의 `GMAIL_REFRESH_TOKEN`은 기존 `default` 계정을 위한 호환 설정입니다.

## 5. Gmail 계정별 등록과 인증

아래 이메일 주소는 예시이므로 실제 사용할 주소로 바꿉니다.

```bash
node index.js account-add personal personal@gmail.com direct
node index.js --account personal gmail-auth

node index.js account-add work work@gmail.com direct
node index.js --account work gmail-auth
```

각 인증 명령에서 출력한 URL을 브라우저로 열고, 등록한 주소와 같은 Google 계정으로 동의합니다. 코드가 실제 인증 주소를 확인하며, 등록한 주소와 다르면 token을 저장하지 않습니다.

등록 상태 확인과 계정 전환은 다음과 같습니다.

```bash
node index.js account-list
node index.js account-use personal
node index.js --account personal gmail-latest
npm run chat:tui
```

`account-list`의 인증 여부는 자격 증명 설정의 존재 여부입니다. 실제 token이 유효한지는 API 호출에서 확인됩니다. `gmail-latest`에서 최근 Claude 메일을 찾지 못했다는 메시지가 나오면 해당 사서함에 검색 조건에 맞는 메일이 있는지도 확인하세요.

Gmail 인증과 Claude 로그인은 별도 단계입니다. Gmail 인증을 완료한 뒤 채팅 메뉴의 **1번**에서 Claude 로그인을 진행합니다. 계정 추가·전환은 **9번**, 현재 계정의 Gmail 인증은 **10번**에서도 가능합니다.

계정 데이터 위치와 기존 단일 계정 호환 방식은 [계정 설정과 기존 환경 이전](계정-설정과-이전.md)을 참고하세요.

## 6. Testing 상태와 반복 인증

External 앱의 게시 상태가 **Testing**이고 Gmail 권한을 요청하면, 발급된 refresh token은 **7일 후 만료**됩니다. 이 프로젝트의 `gmail.readonly`는 기본 프로필 정보만 요청하는 예외에 해당하지 않습니다. [Google refresh token 만료 안내](https://developers.google.com/identity/protocols/oauth2#expiration)

장기 사용 시에는 Audience에서 **In production** 전환을 검토합니다. 전환 후에는 계정별 인증 명령을 다시 실행해 새 자격 증명을 저장하는 흐름으로 진행하세요. 게시 상태 전환과 Google의 앱 검증 완료는 서로 다른 절차입니다.

In production에서도 사용자의 권한 철회, Gmail 권한이 포함된 계정의 비밀번호 변경 등으로 token이 무효화될 수 있습니다. 재인증이 영구적으로 없어지는 설정은 아닙니다. [Google token 만료 조건](https://developers.google.com/identity/protocols/oauth2#expiration)

## 7. 추후 Gmail relay 서버 분리 시 추가 설정

Google Cloud의 같은 프로젝트에 서버용 **Web application** OAuth 클라이언트를 추가합니다. 서버가 실제로 사용할 HTTPS callback 주소를 **Authorized redirect URIs**에 등록합니다.

```text
https://gmail.example.com/oauth2callback
```

위 주소는 예시이며, 도메인과 경로는 서버 구현 시 확정합니다. Google에 등록한 URI와 서버의 인증 요청에 들어가는 URI는 스킴, 경로, 대소문자, 마지막 슬래시까지 일치해야 합니다. [Google 웹 서버 OAuth 안내](https://developers.google.com/identity/protocols/oauth2/web-server)

| 설정 위치    | 준비할 항목                                                                |
| ------------ | -------------------------------------------------------------------------- |
| Google Cloud | Web application 유형의 OAuth 클라이언트와 승인된 리디렉션 URI              |
| relay 서버   | 서버용 Client ID·secret, callback 처리, 계정별 Google refresh token 저장소 |
| relay 서버   | 인증 세션 생성·조회, 계정별 접근 권한 확인, 최신 Claude 메일 조회 API      |
| 현재 CLI     | `GMAIL_RELAY_SERVER_URL`, 서버가 요구하는 경우 `GMAIL_RELAY_API_KEY`       |

서버 배포가 끝나면 현재 CLI의 `.env`를 설정합니다.

```env
GMAIL_RELAY_SERVER_URL=https://gmail.example.com
GMAIL_RELAY_API_KEY=
```

새 계정을 relay 방식으로 추가하려면 다음과 같이 실행합니다.

```bash
node index.js account-add remote remote@gmail.com relay
node index.js --account remote gmail-auth relay
node index.js account-use remote
```

이미 등록한 계정의 연결 방식을 바꾸려면 계정을 다시 추가하지 않고 인증 방식만 지정합니다.

```bash
node index.js --account work gmail-auth relay
```

인증에 성공하면 해당 계정은 relay 방식으로 전환됩니다. Google refresh token은 서버가 보관하고, 현재 CLI에는 해당 계정의 relay session token과 서버 주소를 저장합니다. API 요청·응답 형식은 [Gmail relay 서버 연동 규격](지메일-중계-서버-연동-규격.md)을 참고하세요.

현재 저장소에는 운영용 Gmail relay 서버가 포함되어 있지 않으므로, Google 설정만으로 relay 연결이 완성되지는 않습니다.

## 8. 개인 사용과 외부 공개 시 검증 요건

`gmail.readonly`는 Google이 분류하는 **제한된 권한 범위**입니다. 본인만 사용하거나 개인적으로 아는 소수의 사용자가 사용하는 앱은 검증 예외에 해당할 수 있습니다. 미검증 앱에는 사용자 수 제한 등이 적용됩니다. [Google 제한된 권한 검증 및 개인 사용 예외](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)

외부 사용자에게 서비스를 공개하고 서버를 통해 Gmail 데이터를 처리한다면, 적용되는 OAuth 검증 및 보안 평가 요건을 확인해야 합니다. 검증 대상 앱은 앱 정보, 홈페이지·개인정보처리방침, 도메인 소유권 확인 등도 준비해야 합니다. 실제 사용 범위와 예외 해당 여부를 기준으로 진행합니다. [Google 검증 준비 절차](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)
