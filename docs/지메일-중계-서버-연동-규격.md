# Gmail relay 연동 규격

현재 구현은 relay 클라이언트입니다. 아래 규격으로 별도 서버를 구현하면 Claude 로그인 코드는 그대로 사용할 수 있습니다. `test/oauth-relay.test.js`의 로컬 HTTP 서버가 요청·응답 예시와 회귀 검증을 제공합니다.

## 공통

- 원격 서버는 HTTPS를 사용합니다. HTTP는 `localhost`, `127.0.0.1`, `[::1]`에서만 허용합니다.
- 선택 설정: `GMAIL_RELAY_API_KEY`를 `x-api-key` 헤더로 전달합니다.
- 인증 완료 후: 선택한 계정의 session token을 `Authorization: Bearer <token>`으로 전달합니다.
- 응답은 JSON이며 성공은 2xx, 실패는 4xx/5xx입니다. CLI는 오류 응답 본문 대신 상태 코드를 보고합니다.
- 리다이렉트는 따르지 않습니다. 기본 요청 제한 시간은 `REQUEST_TIMEOUT_MS=30000`입니다.
- 서버 URL에 자격 증명, query, fragment를 넣지 않습니다. `/relay` 같은 경로 접두사는 지원합니다.

## 1. 인증 세션 생성

`POST /api/auth/start`

```json
{ "delivery": "session", "userEmail": "work@gmail.com" }
```

```json
{
  "sessionId": "unpredictable-one-time-id",
  "authUrl": "https://gmail.example.com/oauth/start?session=example",
  "expiresInMs": 300000
}
```

`sessionId`와 `authUrl`은 필수입니다. `expiresInMs`는 양수 밀리초이며 생략 시 5분입니다. 클라이언트는 사용자에게 인증 URL을 표시하고 상태를 조회합니다. Google 동의 완료가 필요합니다.

## 2. 인증 상태 조회

`GET /api/auth/session/<URL-encoded-sessionId>`

진행 중:

```json
{ "status": "pending" }
```

성공:

```json
{
  "status": "authorized",
  "sessionToken": "account-scoped-opaque-token",
  "email": "work@gmail.com"
}
```

실패 상태는 `error`, `expired`, `denied` 중 하나입니다. 다른 상태나 성공 응답의 token·email 누락은 오류로 처리합니다. 클라이언트는 `GMAIL_RELAY_POLL_MS` 주기로 최대 `GMAIL_AUTH_TIMEOUT_MS` 동안 기다립니다.

서버는 Google callback의 `state`와 실제 Gmail 주소를 검증해야 합니다. `email`은 입력한 힌트를 그대로 돌려주지 말고 Google이 확인한 주소를 반환해야 합니다. 세션 ID에는 충분한 엔트로피와 짧은 만료 시간을 부여하고, 인증 결과 조회를 세션 생성자에게 제한하세요. session token은 한 사서함에만 접근할 수 있어야 합니다.

## 3. 최신 Claude 메일

`GET /api/gmail/latest?query=...&maxResults=20&allowMissing=true`

계정은 Bearer token으로 결정합니다. 요청의 이메일이나 로컬 계정 ID로 권한을 바꾸면 안 됩니다.

```json
{
  "ok": true,
  "query": "newer_than:30d",
  "messageId": "gmail-message-id",
  "threadId": "gmail-thread-id",
  "internalDate": 1770000000000,
  "from": "Claude <no-reply@anthropic.com>",
  "subject": "Claude 로그인",
  "date": "mail date header",
  "snippet": "메일 요약",
  "text": "메일 본문",
  "links": [{ "text": "로그인", "url": "https://claude.ai/..." }],
  "verificationLinks": [{ "text": "로그인", "url": "https://claude.ai/..." }],
  "verificationCode": null
}
```

`internalDate`는 Unix epoch **밀리초 숫자**입니다. 로그인 코드는 메일의 시간과 요청 시간을 비교합니다. `messageId`와 `verificationLinks` 배열은 필수입니다. `maxResults`는 1~500 정수입니다.

메일이 없고 `allowMissing=true`이면 HTTP 200과 JSON `null`을 반환합니다. 그 밖에는 오류로 응답합니다. `{ "mail": ... }` 같은 envelope는 사용하지 않습니다.

서버에서도 `src/gmail/latest-claude-mail.js`의 `findLatestDirectMail`과 `src/gmail/message-parser.js`를 재사용하거나 같은 정규화 규격을 구현할 수 있습니다. OAuth 토큰 저장소, token 검증·철회, 사용자별 권한, 서버 배포는 서버 측 책임입니다. Google refresh token을 CLI에 반환할 필요가 없습니다.

## 검증 범위

자동 테스트는 로컬 모의 서버로 인증 시작·완료, 계정별 Bearer token, 검색 옵션, 메일 없음, HTTP 오류, 잘못된 JSON, timeout을 검증합니다. 운영 서버의 배포·TLS·Google OAuth까지 검증하는 테스트는 아닙니다.
